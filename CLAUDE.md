# Track Catcher — правила для Claude

Тут лише правила й карта. Стан — `STATUS.md`. Задачі — `TODO.md`. Історія рішень і проблем — `docs/PROJECT_LEDGER.md`.
Звідки взялося кожне правило (Renault Docs, Dorama, Visualizer, YTM) — `docs/RULES.md`.

## Власник

- **faric** (`faric-ua`). Працює **лише з телефона** (Samsung Galaxy A26 5G) через Termux-меню. Не програміст.
- Відповідати українською, коротко, простими словами. Дії на телефоні — **тільки пунктами меню** (напр. `Track Catcher → 2`), без команд.
- Кожна робоча відповідь закінчується блоком **«Від тебе зараз:»**.
- Усе, що faric має скопіювати (команда, текст), — **окремим блоком коду** (```), щоб у чаті була кнопка «Копіювати». Перед блоком — куди вставити (напр. «у Termux»). Не в рядку тексту, не як посилання. Файли — карткою для завантаження.
- Під час перевірки на телефоні — **один крок за раз**, одне прохання про скрін.
- Якщо faric каже «поки нічого не роби» — лише записати й чекати.

## Старт сесії

1. Прочитати `CLAUDE.md` → `STATUS.md` → `TODO.md`.
2. Неясно, що робити, — одне питання.

## Цикл роботи

1. Код + тести у своїй копії → гілка `feat/…` / `fix/…` / `docs/…` → PR у `main`.
2. Зелений CI (`Checks`, `Android`) → мерж (squash) самому.
3. Нова версія для телефона = підняти `versionName` (X.Y.Z) **і** `versionCode` в `android/app/build.gradle.kts`. Мерж у `main` сам публікує реліз `vX.Y.Z` (лише з ключем підпису, лише якщо такого тегу ще нема).
4. Дати faric шлях: `Track Catcher → 2` (встановити реліз) і що перевірити.
5. Результат («пас / не пас», скрін) — записати в `STATUS.md` (таблиця + журнал) і `docs/PROJECT_LEDGER.md`.

## Докази (не плутати)

- Перевірка коду ≠ юніт-тест ≠ зелений CI ≠ **phone PASS**. Телефон — джерело правди.
- Три окремі стани: версія в репо · опублікований реліз · встановлено на телефоні.
- Не ставити «пас» за власника. Не давати тести для збірки, яку ще не можна встановити.

## Заборонено

- Просити видалити застосунок, чистити дані, перевстановлювати.
- Мовчки видаляти файли власника; будь-яке видалення в застосунку — з вікном підтвердження.
- Класти в репо ключі, паролі, записи (`*.wav`, `*.mp3`), особисту пошту — **репо публічне** (`scripts/audit_repo.py` у CI).
- Перезаписувати тег релізу; публікувати APK без стабільного ключа.
- Зсувати номери пунктів меню (нове — наступним вільним номером).
- `git reset --hard`, `git clean`, force-push у скриптах телефона.
- Стандартні сірі діалоги/кнопки Android, кольори поза `Palette.kt`, галочки ✓ (`scripts/audit_ui.py` у CI).

## Технічне

- Gradle 8.13 **без wrapper** (CI — setup-gradle; телефон — `~/gradle/gradle-8.13`). AGP 8.13.2, Kotlin 2.3.21, SDK 36, minSdk 29.
- Тести: `python3 -m unittest discover -s tests`; Kotlin-юніт-тести лише в CI (у середовищі Claude немає Android SDK і Maven).
- Логи Actions недоступні — усе важливе CI виводить анотаціями: `gh api repos/faric-ua/faric-track-catcher/check-runs/<id>/annotations`.
- Збірка для телефона — `assembleRelease` без мініфікації (не debuggable → MP3 кодується швидко).
- Ключ підпису: створює телефон (меню 7) → секрети `TC_*` у GitHub. Телефон зберігає `~/.android/track-catcher.jks` + `track-catcher-signing.properties`.
