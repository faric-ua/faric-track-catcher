## v0.1.0 / build 1 — перша повна версія — 2026-10-13

**Що хотіли (faric, 15:06).** «Стилізовано оформити все з самого початку; подивитися інші проєкти — правила, аудити, перевороти; кнопки, розташування в книжковому й альбомному виді; скомпонувати правила для цього додатка і зробити від початку до кінця».

**Що зробили.**
1. Пройшли чотири репо (Renault Docs, Dorama, Visualizer, YTM) і звели правила — `docs/RULES.md` (джерело кожного правила).
2. Ядро без Android — `TrackSplitter` (буфер + розріз по тиші ±2 с біля сигналу зі шторки), `Classifier` (повний / неповний / невдало / пропущено), `LevelAnalysis` (обрізання тиші), `WavHeader` (LIST/INFO), `Id3v2` (UTF-16, обкладинка), `Mp3Encoder` (jump3r). 29 юніт-тестів.
3. Android: `CaptureService` (AudioPlaybackCapture, фонова служба `mediaProjection`, після «Стоп» — `dataSync` для дозбереження), `NowPlayingTracker` (усі плеєри, активний — той, що грає; повтор пісні — з перевіркою через 1,5 с), `FileSegmentSink` (шматки на диску + `.json`, відновлення після закриття), `SegmentFinisher` (MediaStore → «Музика › Track Catcher»), `HistoryDb` (SQLite).
4. Інтерфейс: три вкладки, книжкова й альбомна (≥ 600 dp — дві колонки), власні вікна замість стандартних, індикатор рівня як на касетній деці. Контракт — `docs/UI_STYLE_CONTRACT.md`.
5. CI: тести + **ffprobe-самоперевірка** справжніх WAV/MP3; підписаний реліз з `main`; аудит інтерфейсу й публічного репо; знімки екранів на емуляторі.
6. Termux-меню: 1 оновити, 2 встановити реліз, 3 статус, 4 папка, 7 ключ, 8 копія ключа, 9 ярлик, 11 збірка на телефоні.

**Проблеми й рішення (урок).**
- *Maven недоступний із середовища Claude* → не перевірити API бібліотеки MP3. **Рішення:** службовий workflow завантажив jump3r у CI, розпакував вихідний код і запушив у гілку `diag/jump3r-out`. Виявилось, що зручний клас `LameEncoder` тягне `javax.sound` (його немає в Android). Ініціалізацію повторили самі; перевірили локально (Java): 4 хв стерео 320 кбіт/с кодуються за ~8 с на ПК. **Урок:** чого не видно звідси — змусь CI показати це й покласти в гілку.
- *Секрети GitHub недоступні через проксі Claude* → ключ підпису не покласти з боку Claude. **Рішення:** ключ створює телефон (меню 7) і сам передає в секрети через `gh` — як Visualizer (пункти 5/6/7). Ключ не проходить через чат і не лежить у репо. **Урок:** у Dorama пароль ключа лежить у файлі репо — для публічного репо так не можна.
- *Debug-збірка повільна для кодування MP3* (debuggable вимикає частину оптимізацій). **Рішення:** для телефона — `release` без мініфікації, підписаний стабільним ключем.
- *Аудит публічного репо спіймав сам тест*: зразок «пошти» й «пароля» лежав у тесті як текст, а правило «пароль» спрацювало на змінну Gradle `storePassword = tcStorePassword`. **Рішення:** правило — лише формат `.properties` (`storePassword=значення`), зразки в тесті складаються з частин. **Урок:** аудит, що бреше, ігнорують — правило має бути точним.
- *Android 13+ «обмежені налаштування»*: застосунку, встановленому з файлу, сірий перемикач «Доступ до сповіщень». **Рішення:** підказка й кнопка «Відкрити «Про застосунок»» прямо в картці дозволів.
- *Android 15 QPR1+ сам зупиняє запис (MediaProjection), коли екран блокується* (developer.android.com/media/grow/media-projection). А задум — 10–20 пісень підряд з вимкненим екраном. **Рішення:** «Нічний екран» під час запису — чорне тло, яскравість ~1 %, екран не гасне сам, тож блокування не настає; якщо Android усе ж зупинив запис — записане зберігається, а на екрані пояснення простими словами. **Урок:** перед тим як обіцяти «з вимкненим екраном», перевір свіжі зміни Android. На телефоні (One UI) — ще перевірити.
- *Android 14+ вікно запису* пропонує «один застосунок / весь екран»; для звуку з будь-якого плеєра потрібен весь екран. **Рішення:** `MediaProjectionConfig.createConfigForDefaultDisplay()` — одразу «весь екран».

**Що це ще не робить.** На телефоні нічого не перевірено (Phone QA: NOT RUN). Чи зупиняє One UI запис при блокуванні — невідомо до тесту. Невідомо, які плеєри дадуть себе записати. Розпізнавання повтору однієї пісні — лише в коді.

**Чим довели.** CI PR #1: Kotlin компілюється, юніт-тести зелені; ffprobe: `selftest.mp3` — mp3, 48000 Гц, 2 канали, 320 кбіт/с, теги «Обійми / Океан Ельзи / Земля»; `selftest.wav` — pcm_s16le, 48000 Гц, 2 канали, ті самі теги. Python-контракти 22/22, аудит інтерфейсу 10/10, аудит репо PASS.
