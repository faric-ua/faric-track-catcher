# Правила Track Catcher і звідки вони взялися

Зведено 13.10.2026 з чотирьох репозиторіїв faric-ua. Кожне правило — з досвіду, часто після помилки. Тут записано, що взяли і чому.

## Як працюємо (з інструкцій проєкту faric-ua і Renault Docs `CLAUDE.md`)

| Правило | Джерело | Чому |
|---|---|---|
| Старт: `CLAUDE.md` → `STATUS.md` → `TODO.md` | Renault, Dorama | Новий чат не пам'ятає попереднього — стан має бути в репо. |
| Код → гілка → PR → зелений CI → мерж самому | Renault | Власник не програміст; CI — перша перевірка. |
| Відповідь закінчується «Від тебе зараз:» | проєкт faric-ua | Одразу видно, що робити власнику. |
| Дії на телефоні — лише пунктами меню | Renault `RESPONSE_CONTRACT.md` | Команди з телефона легко надрукувати з помилкою. |
| Тест — один крок за раз, один скрін | Renault, Dorama `APK_DELIVERY_RULES.md` | Інакше незрозуміло, на якому кроці зламалось. |
| `STATUS.md` переписується, історія — у журналі | Renault | Статус має читатись за хвилину. |
| Журнал: «Що сталося / Причина / Урок / Що зробили / Чим довели» | Renault `PROJECT_LEDGER.md` | З нього буде урок з програмування. |
| Один список задач з номерами T1… і станами ☐ ◐ ☑ ✔ | Dorama `TODO.md` | Після трьох паралельних списків у Dorama все звели в один. |

## Докази (Visualizer `VISUALIZER_ASSISTANT_WORKFLOW.md`, YTM §21)

- Перевірка коду ≠ юніт-тест ≠ зелений CI ≠ **phone PASS**. Телефон — джерело правди.
- Версія в репо, опублікований реліз і встановлене на телефоні — три різні стани.
- Не ставити «пас» за власника; не давати тести для збірки, яку не можна встановити.

## Меню телефона (Dorama `menu.sh`, Renault `menu.sh`)

- Номери пунктів ніколи не зсуваються; нове — наступним вільним номером.
- Оновлення меню — лише fast-forward; локальні зміни, інша гілка чи розбіжність → стоп, нічого не стирається.
- Ніяких `reset --hard`, `clean`, force-push.
- Меню саме оновлюється при запуску; ярлик Termux:Widget — один дотик.

## Інтерфейс (Renault `Ui.kt`, Visualizer `UI_STYLE_CONTRACT.md`, YTM `UiChrome.kt`)

Повністю — у `docs/UI_STYLE_CONTRACT.md`. Коротко:
- Темна тема; кожен новий елемент успадковує стиль найближчого (Visualizer).
- Ніяких стандартних сірих діалогів і кнопок (Visualizer, YTM) — CI-перевірка.
- Вибране — зелена рамка без ✓ (Renault v0.5.117: галочка з'їдала ширину, і текст стрибав).
- Зона дотику ≥ 48 dp; довгі українські підписи переносяться, шрифт не зменшується (Visualizer).
- «Скасувати/Закрити» — праворуч (YTM UX-018).
- Видалення — тільки з вікном підтвердження; відкрите вікно переживає поворот (Renault `RestorableDialogs`).
- Дві колонки — за реальною шириною екрана (≥ 600 dp), а не за поворотом (Renault).
- Поворот відновлює стан і нічого не перезапускає (Visualizer `UI_LIFECYCLE_ROTATION_AUDIT.md`).

## Публічний репо (YTM `PRIVACY.md`, Visualizer `validate.yml`)

- Ні ключів, ні паролів, ні записів, ні особистої пошти — `scripts/audit_repo.py` у CI.
- Записи лишаються на телефоні; в інтернет застосунок ходить лише по оновлення з Google Диска автора (v0.1.15).
